# Pulse at a glance

Pulse is a small customer-feedback inbox with two main parts: a **React web app** that support staff use, and an **Express API** that reads and updates a **SQLite database**.

```text
Browser
  React app: login, inbox, item details
       │ HTTP requests + bearer token
       ▼
  Express API
  ├── auth and feedback routes
  ├── summary generation
  └── SQLite queries
       │
       ▼
  server/pulse.db
  users · customers · feedback · feedback_notes
```

## How a typical interaction works

1. You sign in. The browser sends email and password to `POST /login`; the API looks up the user and returns a token.
2. The browser stores that token and includes it in the `Authorization` header for most later requests.
3. The inbox requests `GET /feedback` and `GET /metrics`. The API queries the database and returns feedback rows and counts.
4. When you open a row, the detail view requests the item, customer profile/history, users, and notes.
5. Changes such as resolving an item or adding a note go back to the API as `POST` requests; the API writes them to SQLite.
6. Summary generation sends the item ID to `POST /summarize`; the server fetches its message and passes it to the summary helper.

## Main API routes

| Route | Purpose |
|---|---|
| `POST /login` | Check credentials and return a token |
| `GET /feedback` | List feedback with status, search, and page parameters |
| `GET /feedback/:id` | Load one item |
| `POST /feedback/:id/resolve` | Toggle open/resolved status |
| `POST /feedback/:id/assignment` | Save owner, priority, and due date |
| `GET/POST /feedback/:id/notes` | Read or add internal notes |
| `GET /customers/:id` | Load a customer and recent feedback history |
| `GET /users` | Load team members for assignment |
| `GET /metrics` | Load open, resolved, urgent, and overdue counts |
| `GET /export.csv` | Download matching feedback as CSV |
| `POST /summarize` | Generate a short message summary |

## A few details to keep in mind

- The app is intentionally small: API routes and SQL are concentrated in one file, rather than split into controllers, services, and repositories.
- The UI and API mostly pass plain JSON objects that line up with the types in `types.ts`.
- The README says the default setup works offline: summaries use canned text unless configured to call OpenAI. See [README.md](/Users/macbook/test/engineer-challenge-2026-public/README.md) for setup and sample login details.
- Some implementation choices are worth noticing while exploring: the feedback list’s page offset is calculated as `page * PAGE_SIZE` (so page 1 starts after the first 10 rows), and the auth middleware decodes the token without verifying its signature. These are useful landmarks if you later investigate behavior or security.

For an efficient guided read, start with `App.tsx` → `Inbox.tsx` → `api.ts` → `server/src/index.ts`; then read `ItemDetail.tsx` for the item workflow.
